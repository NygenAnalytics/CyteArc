# Repertoire API reference

Single-cell immune profiling reads the T cell receptor (TCR) or B cell receptor (BCR) of each cell beside its transcriptome. A V(D)J library, such as 10x Genomics Chromium Single Cell Immune Profiling, assembles each cell's receptor transcripts into contigs: one chain each, with its locus, its V, D, J and constant genes, and its junction, the CDR3 with the conserved cysteine and phenylalanine or tryptophan on either side. A T cell receptor pairs an alpha chain (TRA) with a beta chain (TRB), or a gamma chain (TRG) with a delta chain (TRD), and a B cell receptor pairs a heavy chain (IGH) with a kappa (IGK) or lambda (IGL) light chain. `cytearc.repertoire` holds the record of the imported receptors and the constants of the receptor model; contig fields keep their names in the AIRR Community's Rearrangement schema ([Vander Heiden et al. 2018](https://doi.org/10.3389/fimmu.2018.02206)).

The steps run on a `DataStore` whose cells are the cells of the expression library. {meth}`ds.repertoire.import_receptors <cytearc.datastore.namespaces.RepertoireAccessor.import_receptors>` reads the contigs of those cells and saves an `immune_receptors` artifact, {meth}`ds.repertoire.load_receptors <cytearc.datastore.namespaces.RepertoireAccessor.load_receptors>` reads it as an {class}`~cytearc.repertoire.ImmuneReceptors` record, and {meth}`ds.plots.receptor_qc <cytearc.datastore.plot_accessor.DataStorePlotAccessor.receptor_qc>` plots the receptor types, chain pairings and chains per cell. {meth}`ds.repertoire.clonotypes <cytearc.datastore.namespaces.RepertoireAccessor.clonotypes>` groups the cells into clonotypes, by identical or by similar junctions, and saves a `clonotypes` artifact, which {meth}`ds.repertoire.load_clonotypes <cytearc.datastore.namespaces.RepertoireAccessor.load_clonotypes>` reads as a {class}`~cytearc.repertoire.Clonotypes` record; the clone summaries that the {doc}`clones` describes measure clonotypes, each receptor type apart. {meth}`ds.repertoire.gene_usage <cytearc.datastore.namespaces.RepertoireAccessor.gene_usage>` counts the genes of groups' chains as a {class}`~cytearc.repertoire.GeneUsage` record, {meth}`ds.repertoire.spectratype <cytearc.datastore.namespaces.RepertoireAccessor.spectratype>` their junction lengths as a {class}`~cytearc.repertoire.Spectratype` record, and {meth}`ds.plots.gene_usage <cytearc.datastore.plot_accessor.DataStorePlotAccessor.gene_usage>`, {meth}`ds.plots.gene_pairing <cytearc.datastore.plot_accessor.DataStorePlotAccessor.gene_pairing>` and {meth}`ds.plots.spectratype <cytearc.datastore.plot_accessor.DataStorePlotAccessor.spectratype>` plot them. {meth}`ds.repertoire.export_airr <cytearc.datastore.namespaces.RepertoireAccessor.export_airr>` writes the contigs, with each cell's clonotype, as an AIRR Rearrangement file. [Immune repertoires](../tutorials/immune-repertoires) runs these steps on the blood cells of a healthy donor.

## Import contigs

`import_receptors` reads two kinds of file and tells them apart by their header; `format="cellranger"` or `format="airr"` names the format of every file instead:

| File | Written by | Holds |
|---|---|---|
| `filtered_contig_annotations.csv` | Cell Ranger, in `outs/` of `cellranger vdj` or `outs/per_sample_outs/<sample>/vdj_t/` and `vdj_b/` of `cellranger multi` | The contigs that Cell Ranger assembled with high confidence in the barcodes it calls cells |
| `all_contig_annotations.csv` | Cell Ranger | Every contig; those outside a called cell or of low confidence are kept but do not count as chains |
| AIRR Rearrangement TSV | Cell Ranger (`airr_rearrangement.tsv`) and other pipelines that write the AIRR schema | One row per contig with the AIRR fields; single-cell files name each contig's cell in `cell_id` |

Cell Ranger's columns take their AIRR names: `barcode` becomes `cell_id`, `contig_id` `sequence_id`, `chain` `locus`, `v_gene`, `d_gene`, `j_gene` and `c_gene` become `v_call`, `d_call`, `j_call` and `c_call`, `cdr3` and `cdr3_nt` become `junction_aa` and `junction`, since Cell Ranger's CDR3 includes the conserved residues of the junction, `umis` `umi_count` and `reads` `consensus_count`. An AIRR file without `locus` has each contig's locus inferred from its gene calls, as the one locus that all of them name; a V call such as `TRAV29/DV5`, of a gene that alpha and delta chains share, takes no part. Every file needs a contig ID, a locus or gene calls, a junction amino-acid sequence and a productive flag, and an AIRR file also a `cell_id`; another pipeline's AIRR file reads as Cell Ranger's does when it holds them. `cytearc.repertoire.FIELDS` lists the fields that an import keeps, and other columns are not kept. Files may be plain or gzip-compressed, whatever their names, and are read as every delimited table is ([clone tables](clones.md#import-clones-from-a-file) state the rules): blank lines hold no contig, a row of fewer or more fields than the header is refused naming its line, and a file whose every row ends in its separator is refused until its header ends in the separator too. AIRR files are read without quoting, as the format writes them, so a double quote is part of its value, also at the start of one, and a file whose writer quoted values, as the airr library's writer quotes a value that holds a double quote, keeps those quotes; Cell Ranger's CSVs keep their quoting.

Pass the TCR and BCR files of one library together, so a cell with both kinds of chain is found:

```python
cells = ds.snapshot_cell_selection()
receptors = ds.repertoire.import_receptors(
    ["vdj_t/filtered_contig_annotations.csv", "vdj_b/filtered_contig_annotations.csv"],
    cell_selection=cells,
)
table = ds.repertoire.load_receptors(receptors)
table.cells["chain_pairing"].value_counts()
ds.plots.receptor_qc(receptors, group_by="sample")
```

### Join barcodes to cells

A contig's cell ID is its file's `barcode_prefix`, its barcode and `barcode_suffix`, matched exactly, and `barcode_pattern` keeps the part of each barcode that its named group `barcode` matches first, as {meth}`ds.clones.import_clones <cytearc.datastore.namespaces.ClonesAccessor.import_clones>` joins barcodes. Each option takes one value for every file or one per file. A merged store names cells `<sample>__<barcode>`, so pass each sample's files with that sample's prefix:

```python
receptors = ds.repertoire.import_receptors(
    ["s1/vdj_t.csv", "s1/vdj_b.csv", "s2/vdj_t.csv", "s2/vdj_b.csv"],
    cell_selection=cells,
    barcode_prefix=["s1__", "s1__", "s2__", "s2__"],
)
```

Contigs whose barcode matches no selected cell, such as the contigs of barcodes that the expression library did not call cells, are counted: the artifact's {ref}`diagnostics <artifact_diagnostics>` hold the join's counts of their barcodes by the cell ID they name, those of no cell of the store apart from those of cells outside the selection, then `fileContigs` and `unmatchedContigs`, the files' contigs and those that match no selected cell, and `cellsWithChain`, the selected cells with a chain. A warning names up to five barcodes of no cell, and an import that reuses the saved receptors gives the warning again. A selected cell without contigs is kept, with the receptor type `"no IR"`.

Saved receptors are reused when each file holds the same bytes and has the same format ({ref}`reuse of imports <import_reuse>`). A contig of a selected cell without an ID raises `ValueError`, as does a contig ID that repeats among the contigs of selected cells within one file; the contigs of other barcodes are only counted; the same ID in two files, such as `<barcode>_contig_1` in the TCR and the BCR file of one cell, is allowed. An import holds each distinct gene call and junction once, as bytes, with a code per contig, and each contig's ID, sequence and alignments as bytes of their own. Its memory grows with those bytes, up to three times them at its peak while it orders the contigs, and with the selected cells, each with its ID as a Python string; it parses its files in chunks of as many rows as half of what the budget leaves holds. An import that would not fit the memory budget is refused with a `MemoryError` before it writes anything, a `MemoryBudgetError` at each step that it charges ([what a refusal names](../concepts/memory-and-execution)). Encoded contigs take about 130 bytes each in Cell Ranger's annotations without region sequences, about 800 with them, and about 1,500 in AIRR files with sequences and alignments, so a million cells with two contigs each of the first kind need about 1.1 GB.

## Chains of each cell

CyteArc follows the receptor model of scirpy ([Sturm et al. 2020](https://doi.org/10.1093/bioinformatics/btaa611)). A cell has up to two chains of each arm of its receptor: the VJ arm, of the chains that join V and J segments (TRA, TRG, IGK, IGL), and the VDJ arm, of those that also join a D segment (TRB, TRD, IGH). Allelically included cells, with two alpha or two light chains, keep both.

A contig counts as a chain when it has the locus of a receptor chain and a junction amino-acid sequence, is productive, and is not flagged by Cell Ranger as outside a called cell (`is_cell`) or of low confidence (`high_confidence`). `productive_only=False` counts non-productive contigs too, such as the second, unproductive rearrangement of an allelically excluded cell. Within each arm, chains are ranked by UMI count (`umi_count`), then by AIRR's deprecated `duplicate_count`, which some files hold instead, then by read count (`consensus_count`), each most first and a missing count as 0, then by the junction nucleotide and amino-acid sequences, the one later in sort order first, as scirpy ranks them, and last by contig ID, so the ranking never depends on file order. The first two chains of each arm fill the cell's `VJ_1`, `VJ_2`, `VDJ_1` and `VDJ_2` slots, and a cell with more than two chains of an arm is a multichain cell, often a doublet.

The slots give each cell three labels, with scirpy's categories and rules:

| Label | Values |
|---|---|
| `receptor_type` | `"TCR"` (only T cell receptor chains), `"BCR"` (only B cell receptor chains), `"ambiguous"` (both), `"multichain"`, `"no IR"` (no chain) |
| `receptor_subtype` | `"TRA+TRB"` and `"TRG+TRD"` (chains of that receptor only), `"IGH"` (heavy chains only), `"IGH+IGK"` and `"IGH+IGL"` (light chains of one kind, with or without heavy chains), `"IGH+IGK/L"` (heavy chains with kappa and lambda chains), `"ambiguous"` (any other combination, such as TRA with TRD, or kappa and lambda chains without a heavy chain), `"multichain"`, `"no IR"` |
| `chain_pairing` | `"single pair"` (one chain of each arm), `"orphan VJ"` and `"orphan VDJ"` (chains of one arm only), `"extra VJ"` and `"extra VDJ"` (a pair and a second chain of that arm), `"two full chains"` (two chains of each arm), `"ambiguous"` (an ambiguous subtype), `"multichain"`, `"no IR"` |

Only the slots count towards the type and subtype, so a multichain cell's further chains decide nothing but its `"multichain"` label. `cytearc.repertoire` exports the categories in display order as `RECEPTOR_TYPES`, `RECEPTOR_SUBTYPES` and `CHAIN_PAIRINGS`.

The artifact's canonical `values` hold each cell's receptor type, and its other per-cell arrays are `receptor_subtype`, `chain_pairing`, `multichain`, `n_vj` and `n_vdj` (the cell's chains of each arm, before the slots keep two) and `n_contigs` (its imported contigs, chains or not). The labels group cells like cluster labels do: `ds.select_cells(receptors, include=["TCR"])` keeps the T cells with a receptor, `ds.select_cells(receptors, value="chain_pairing", include=["single pair"])` the cells with one chain of each arm, and `ds.plots.embedding(layout=run["umap"], color_by=receptors)` colours cells by receptor type, in the colours that `receptor_qc` gives them. A colouring artifact must share the layout's cells, so import the receptors of a run's cells with `cell_selection=run["analysis_cell_selection"]`. [Read per-cell values](cell_aligned_kinds) lists the arrays.

On the public 10x Genomics run "Human PBMC from a Healthy Donor, 10k cells (v2)" (CC BY 4.0), with the TCR and BCR files imported together for the cells of its expression matrix, the receptor type, subtype and chain pairing of every cell, and the locus, gene calls, junction and junction amino-acid sequence in every slot, equal those of scirpy 0.25.1 from `read_10x_vdj`, `merge_airr`, `index_chains` and `chain_qc`: for the filtered and the unfiltered contig annotations of the Cell Ranger 4.0.0 release, 10,553 cells, whose files write `True` and `None` and whose filtered contigs include non-productive ones, and of the 5.0.0 release, 10,548 cells, and for the AIRR files of 5.0.0 read with `read_airr`, whose loci both tools infer. The same holds for the 55,206 cells of "CD8+ T cells of Healthy Donor 1" (Cell Ranger 3.0.2), whose unfiltered contig annotations name genes as reference 2.0.0 does, such as `TRAV29DV5`.

## Read and plot receptors

`load_receptors` returns an {class}`~cytearc.repertoire.ImmuneReceptors` record. Its `cells` table holds one row per cell: the three labels, `multichain`, `n_vj`, `n_vdj` and `n_contigs`, and the locus, gene calls, junction, junction amino-acid sequence, UMI count and read count of each slot side by side, such as `VDJ_1_junction_aa`, missing for an empty slot. Its `chains` table holds one row per contig: the cell's `ids`, the contig's `slot` (`""` for a contig in no slot), `chain` (whether it counts as a chain) and its fields. `fields=[...]` loads only those fields, into `chains` and into the slots of `cells`, which matters for files with full sequences and alignments; `fields=[]` loads each cell's labels and chain counts alone.

`ds.plots.receptor_qc` draws cells by receptor type, cells by chain pairing, and cells by their number of chains of each arm, the two arms side by side and three or more chains sharing the last bar, in three panels that stand in one column. Many `"orphan VDJ"` or `"orphan VJ"` cells point to chains lost in capture, and many `"multichain"` or `"ambiguous"` cells to doublets. `group_by` names cell metadata columns, one or several, such as the sample, and `groups` a cell-label artifact, such as a clustering, which may hold fewer cells than the receptors; the groups are the combinations of their labels, as the clone summaries group cells, and each draws one bar stacked by category, the first on top as the legend lists them, of the fraction of its cells unless `normalize=False`. Its tables are `receptor_type` and `chain_pairing`, one row per group and category, zeros included, with `group`, the category and `n_cells`, every cell in the group `"all cells"` without a grouping, so a group may take any name; and `chains_per_cell`, the cells of each number of chains of each arm.

## Define clonotypes

A clonotype groups the cells of one T or B cell clone, which share their receptor because they descend from one cell. `clonotypes` links two cells when the junctions of their chains are identical, as scirpy's `define_clonotypes` does, and takes the connected groups of these links as clonotypes, so a cell whose chains match two cells that do not match each other joins them. The options set which chains must agree:

| Option | Values | Two cells are linked when |
|---|---|---|
| `sequence` | `"nt"`, the default, or `"aa"` | Their junctions are identical in nucleotides, or in amino acids |
| `receptor_arms` | `"all"`, the default | Both arms agree, for cells with a primary chain in both; one arm agrees, for cells with one; a cell with both arms is never linked to a cell with one |
| | `"any"` | Either arm agrees |
| | `"VJ"`, `"VDJ"` | That arm agrees; cells without a chain of that arm have no clonotype |
| `dual_ir` | `"any"`, the default | One chain of an arm matches one chain of the other cell's arm |
| | `"all"` | The cells have the same number of chains in the arm and every chain matches, in either order |
| | `"primary_only"` | The primary chains match; second chains are ignored |
| `same_v_gene`, `same_j_gene` | `False`, the defaults, or `True` | Matched chains also share their V or J gene call |

Cells of different receptor types never share a clonotype unless `within_receptor_type=False`, so the beta chain of an ambiguous cell does not join a T cell clonotype to its heavy chain's B cells, and `within` names cell metadata columns, such as the donor, whose labels keep clonotypes apart: identical receptors of two donors are public receptors, not one clone. Every cell with a receptor needs a label in the `within` columns. A cell without a receptor, or without a compared sequence among the chains that take part, has no clonotype.

```python
clonotypes = ds.repertoire.clonotypes(receptors)  # nucleotide junctions, both arms
same_residues = ds.repertoire.clonotypes(receptors, sequence="aa", within="donor")
table = ds.repertoire.load_clonotypes(clonotypes)
table.clonotypes.head(10)  # the largest clonotypes with their chains
ds.select_cells(clonotypes, value="clone_size", low=2, keep_bounds=True)  # expanded cells
ds.plots.clone_abundance(clonotypes, group_by="sample")
ds.clones.diversity(clonotypes, group_by="sample")  # each sample's T and B cells apart
```

Clonotypes are numbered by size: `clonotype_1` holds the most cells, and clonotypes of equal size follow their receptor type in sorted order, then their `within` labels in natural order, then their sorted chains, so the numbers do not depend on the order of the cells. The artifact's canonical `values` hold each cell's clonotype label, empty for a cell without one, which groupings and `select_cells` treat as missing and embeddings draw in the missing color; `clone_size` holds the cells of each cell's clonotype, 0 without one, and `codes` its number minus one, -1 without one. Defining clonotypes reads the chains of the receptors, not the contig files: a million cells of about two chains each take about 2 s. The memory budget grows with the cells: reading and coding their receptor types, grouping them by their `within` labels, which counts as the clone summaries' grouping does, and 1,000 bytes per cell to define the clonotypes, which leaves room for cells with more chains, beside each contig's code of the compared junction. `load_clonotypes` grows with the cells, the clonotypes and the representatives' values, which it decodes 65,536 at a time. The clonotypes record the receptors, the options and, with `within`, the cells' labels, so defining them again with the same values returns the saved clonotypes. In the record that `load_clonotypes` returns, each cell's `clonotype` is a pandas categorical whose categories are the clonotype labels in rank order.

Each distinct combination of a cell's compared chains, its configuration, gets keys that the rules derive from its chains: under `"any"` one key per chain, under `"all"` the arm's sorted chains as one key, and with both arms required every combination of a VJ and a VDJ key. Two configurations are linked exactly when they share a key, and clonotypes are the connected components of the graph of configurations and keys, so the cost grows with the number of chains rather than the number of pairs of cells.

On "Human PBMC from a Healthy Donor, 10k cells (v2)", 6,189 cells with a receptor, and "CD8+ T cells of Healthy Donor 1", 46,526 cells with a receptor, the clonotypes equal scirpy 0.25.1's `define_clonotype_clusters` with the identity metric, cell for cell, for ten combinations of the options: `"nt"` and `"aa"`, every value of `receptor_arms` and `dual_ir`, the V and J gene matches, and without receptor types. With `dual_ir="all"` they also equal the clone keys of scRepertoire 2.8.0's `combineTCR` for all 5,213 PBMC T cells (`CTnt` with `"nt"`, `CTaa` with `"aa"`, and `CTstrict` with `"nt"` and both gene matches), and Cell Ranger 3.0.2's clonotypes, sets of identical productive junctions, for all 46,342 T cells of donor 1. Cell Ranger 5.0.0 groups clonotypes with enclone, which also merges cells that lack a chain, and agrees for 5,155 of the 5,213 PBMC T cells. On one core, defining the clonotypes of donor 1 takes 0.2 s, where scirpy's `ir_dist` and `define_clonotype_clusters` take 3.9 s on the same cells.

### Clonotype clusters

T cells whose receptors differ by a residue or two often recognize the same epitope, and the B cells of one clone differ by somatic mutations, so identical junctions split groups that belong together. `metric` links chains whose junctions are similar instead, as scirpy's `define_clonotype_clusters` does, under the same rules for arms, dual chains, gene calls, groups and receptor types:

| `metric` | Two junctions are linked when |
|---|---|
| `"identity"`, the default | They are identical; `max_distance` stays None |
| `"hamming"` | They have one length and at most `max_distance` substitutions |
| `"normalized_hamming"` | They have one length and their substitutions are at most `max_distance` percent of it, rounded half up, as scirpy rounds them |
| `"levenshtein"` | At most `max_distance` substitutions, insertions and deletions turn one into the other |

```python
similar = ds.repertoire.clonotypes(receptors, sequence="aa", metric="hamming", max_distance=1)
families = ds.repertoire.clonotypes(  # B cell clonal families
    receptors, sequence="nt", metric="normalized_hamming", max_distance=15,
    same_v_gene=True, same_j_gene=True, within="donor",
)
```

`max_distance` has no default for the distance metrics, since it decides the clusters; scirpy's `cutoff`, the same bound, defaults to 2, which for `normalized_hamming` means 2 percent, and its B cell tutorial passes 15. A `max_distance` of 0 links identical junctions alone under every metric, as in scirpy. The clusters label cells as clonotypes do, every clone summary measures them alike, the saved record holds the metric and `max_distance`, and `clone_abundance` titles its panel of the largest `Largest 20 clonotype clusters`.

Every pair of distinct junctions within `max_distance` is found exactly, by the neighbour search of `cytearc.clones.sequences`, in whichever of two ways is estimated to take less time, chosen for the junctions of each length, or under `levenshtein` for all of them, within each combination of the gene calls that must match. For distances up to 3, two junctions of one length within that many substitutions share a key in which those positions are masked, or, for long texts, the runs of positions that hold them, and two junctions within that many edits share a variant with at most that many positions deleted from each, so only the junctions that share a key are compared. Otherwise every pair of one length, or of lengths within `max_distance`, is compared, which suits fewer junctions with more keys each, such as the nucleotide junctions of B cells with the same gene calls, and larger distances, such as nucleotide junctions at 15 percent. On one core, the 201,576 pairs among a million distinct simulated junctions of 11 to 18 residues, a fifth of them one substitution from another, take 0.66 s within one substitution and 0.96 s within one edit, and the 22,484 pairs among 100,000 such junctions within two take 0.04 s and 0.27 s.

Defining clusters reserves 512 MiB for the search beyond what defining clonotypes reserves, and the memory budget must allow both. Only the junctions that the cells' chains hold are decoded for the search, a chunk at a time, and they count against what the budget leaves as the Python strings they become, so contigs that are not chains, such as non-productive ones, cost nothing. The search holds the encoded junctions, one pass of variant keys with the pairs within `max_distance` that the pass finds, or under `levenshtein` the candidate pairs that share its keys, and 32 bytes for each pair found, and raises `MemoryError` before it would hold more than the reservation and what the budget leaves. Linking the cells then holds 32 bytes for each pair of chains within `max_distance`, and 32 for each link between two such chains of one group, one for each group that holds both, or under `dual_ir="all"` between two arms whose chains match one by one; each is charged to the memory budget before it is allocated, so many pairs, as nucleotide junctions within 3 substitutions or convergent light chains give, raise `MemoryBudgetError` that names the gene matches and a lower `max_distance`. Cells are linked through the chains they share rather than pair by pair: under rules that one arm satisfies, clusters are connected components through each group's chains, and when both arms must match, each cell meets its candidates through the arm whose chains reach the fewest cells, in chunks of 2 million pairs, checked in the other arm. Many cells that share one chain, such as the invariant alpha chain of MAIT cells, so cost no pairs: 40,000 cells that share one of two near alpha chains and differ in their other chains take at most 0.1 s under every rule.

The clusters equal scirpy 0.25.1's `ir_dist` and `define_clonotype_clusters` for every cell of both 10x runs, 6,189 PBMC cells and 46,526 CD8+ cells with a receptor, in nine settings: residues within one and two substitutions with both arms and either chain, within one with every chain matched, with either arm and primary chains, and with the VDJ arm and V gene matches; within one edit with both arms; within two edits with the VJ arm and every chain matched, and with V and J gene matches; and nucleotides within 15 percent with V gene matches. On one thread, a setting takes 0.23 to 1.5 s on the CD8+ cells once the kernels are compiled, where scirpy's `ir_dist` takes 5 to 88 s on four cores and its `define_clonotype_clusters` another 2 to 5 s.

`load_clonotypes` returns a {class}`~cytearc.repertoire.Clonotypes` record. Its `cells` table, indexed by cell `ids`, holds each cell's `clonotype` and `clone_size`, and its `clonotypes` table one row per clonotype, largest first: `clonotype`, `n_cells`, `fraction` (its share of the cells with a clonotype), `n_configurations`, its `receptor_type`, `group`, the name of its cells' `within` group, their labels joined by commas, or `"all cells"` without `within`, and the chains of its representative cell, the first cell of its most frequent configuration, slot by slot, such as `VDJ_1_junction_aa`, `VDJ_1_v_call` and `VJ_1_junction`, as pandas text, missing where the slot is empty. Its `group_keys` holds each `within` group's labels, one row per group indexed by its name, with a column per `within` column under the column's own name, as the clone summaries hold their groups' labels ({ref}`groups and their labels <group_keys>`), so a `within` column may take any name and `table.clonotypes.join(table.group_keys, on="group")` gives each clonotype its labels.

### Measure clonotypes as clones

Clonotypes are clones to every clone summary that the {doc}`clones` describes. {meth}`ds.clones.load_clones <cytearc.datastore.namespaces.ClonesAccessor.load_clones>` reads them as a {class}`~cytearc.clones.Clones` record whose `cells` table also holds each cell's `receptor_type`, {meth}`ds.plots.clone_abundance <cytearc.datastore.plot_accessor.DataStorePlotAccessor.clone_abundance>` draws their sizes, with each of the largest labelled by its representative's junction, such as `CASSLGQAYEQYF`, and also by its number where two of them share a junction, such as `CAVA 1` and `CAVA 3`, {meth}`ds.clones.expansion <cytearc.datastore.namespaces.ClonesAccessor.expansion>`, {meth}`ds.clones.diversity <cytearc.datastore.namespaces.ClonesAccessor.diversity>` and {meth}`ds.clones.rarefaction <cytearc.datastore.namespaces.ClonesAccessor.rarefaction>` measure them within groups of cells, {meth}`ds.clones.overlap <cytearc.datastore.namespaces.ClonesAccessor.overlap>` and {meth}`ds.clones.track <cytearc.datastore.namespaces.ClonesAccessor.track>` compare and follow them across groups, {meth}`ds.plots.clone_tracking <cytearc.datastore.plot_accessor.DataStorePlotAccessor.clone_tracking>` and {meth}`ds.plots.clone_fate_bias <cytearc.datastore.plot_accessor.DataStorePlotAccessor.clone_fate_bias>` label the clonotypes they draw alike, and {meth}`ds.clones.coupling <cytearc.datastore.namespaces.ClonesAccessor.coupling>` and {meth}`ds.clones.fate_bias <cytearc.datastore.namespaces.ClonesAccessor.fate_bias>` measure the fate coupling of groups and the fate bias of early cells. Each summary measures each receptor type apart, since T cell and B cell repertoires are populations of their own: the receptor type joins the groups' key columns as `receptor_type`, so the T cells and B cells of a sample are two groups, named `"s1, TCR"` and `"s1, BCR"`, and without a grouping the groups are the receptor types. Clonotypes that `within_receptor_type=False` defines across receptor types also save each cell's clonotype within its type, which every summary and figure measures, so they measure what the clonotypes within types do, under labels such as `clonotype_1 (TCR 2)` for clonotype_1's second clonotype of T cells, which figures name by its own representative's junction, such as `CASSB (TCR 2)` ({ref}`groups and their labels <group_keys>`); `load_clones` holds those labels in `within_type_clone`. Only groups of one receptor type are compared, coupled or followed together, and the coupling's null shuffles labels within each receptor type. The fates of `fate_bias` name a receptor type each, such as `"Neutrophil, TCR"`, and a late cell without a clonotype has no fate, so each clonotype is tested among the late cells of its receptor type that have a clonotype, where imported clones are tested among every late cell with a fate. `group_by="receptor_type"` is refused, since the labels are kept apart already.

```python
expansion = ds.clones.expansion(clonotypes, group_by="sample")
ds.clones.load_expansion(expansion).categories  # each sample's T and B cells
ds.clones.rarefaction(clonotypes, group_by="sample")
ds.clones.overlap(clonotypes, group_by="sample").pairs  # pairs of one receptor type
ds.clones.export_clones(clonotypes, "clonotypes.csv")  # CoSpar's clone table, format="cospar"
```

## Gene usage and junction lengths

A repertoire's genes and junction lengths summarize how its receptors were assembled: an expanded clone shows its genes and length as peaks, invariant cells such as MAIT and iNKT cells show their gene pairs (TRAV1-2 with TRAJ33, and TRAV10 with TRAJ18), and naive repertoires show smooth length distributions. `gene_usage` and `spectratype` count each cell by its chains in `slots`, by default its primary chain of each arm, `VJ_1` and `VDJ_1`, as scirpy reads a slot, and each chain within its locus, so TRA and TRB genes get their own shares. Nothing is saved.

```python
usage = ds.repertoire.gene_usage(receptors, genes="v_call", group_by="sample")
usage.table  # group, sample, locus, v_call, n_cells, fraction
pairs = ds.repertoire.gene_usage(receptors, genes=("v_call", "j_call"))
families = ds.repertoire.gene_usage(clonotypes, level="family", count="clonotypes")
lengths = ds.repertoire.spectratype(receptors, group_by="sample")
ds.plots.gene_usage(usage)
ds.plots.gene_pairing(ds.repertoire.gene_usage(receptors, genes=("v_call", "j_call"), cell_selection=t_cells))
ds.plots.spectratype(lengths)
```

`genes` names one gene field, `v_call`, `d_call`, `j_call` or `c_call`, or several, such as `("v_call", "j_call")` for the V-J pairs of each chain. `level` names calls as called, with their allele (`"allele"`, such as `TRBV12-3*01`), as genes (`"gene"`, the default, `TRBV12-3`) or as families (`"family"`, `TRBV12`, the locus, segment and first number, so `TRAV29/DV5` becomes `TRAV29` and `IGKV1D-39` `IGKV1`); a call naming several genes, such as `TRBV6-2,TRBV6-3`, keeps its first. `cytearc.repertoire.GENE_FIELDS` and `GENE_LEVELS` list the fields and levels. `spectratype` counts junction lengths in residues (`sequence="aa"`) or nucleotides (`"nt"`), in characters whatever their encoding; a junction includes its conserved cysteine and phenylalanine or tryptophan, as Cell Ranger's CDR3 does. A chain without the counted value is left out.

The `source` is an `immune_receptors` artifact, whose cells with a chain count, or a `clonotypes` artifact, whose cells with a clonotype count; with a clonotypes artifact, `count="clonotypes"` counts each clonotype once per group and value instead of each cell, so expanded clones do not dominate the shares, and clonotypes across receptor types by each cell's clonotype within its type. `count="cells"` counts a cell once for each value, even where two of its slots of one arm, such as `VJ_1` and `VJ_2`, hold chains of that value. The groups are the combinations of the labels of the `group_by` columns and of a `groups` label artifact among the cells of `cell_selection`, grouped as the clone summaries group them; without either, every cell is one group. Each table holds `group`, the group's labels joined by commas (`"all cells"` without groups), `locus`, the counted values, `n_cells` or `n_clonotypes`, and `fraction`, each count's share of the group's counts of that locus, and each record's `group_keys` holds the groups' labels, as the clone summaries hold them ({ref}`groups and their labels <group_keys>`), so a key column may take any name, such as `locus` or `n_cells`. Each record's `diagnostics` counts what it leaves out: `cellsWithoutClone`, the cells kept without a chain in the counted slots, or without a clonotype for a clonotypes source, `cellsWithoutGroup`, those counted but in no group, the `groups`, and `chainsWithoutValue`, the chains of the counted slots without the gene fields or the junction counted. Its rows follow the groups' natural order and then the loci; within a locus, gene usage orders its genes by count, most first, and spectratype its lengths. The figures draw these records. `ds.plots.gene_usage` draws the usage of one gene field, one panel per locus, the `max_genes` (30) genes with the most chains as a heatmap of fractions by group, which names the group even where one group holds the locus, or as bars in the locus's colour without a grouping; `ds.plots.gene_pairing` draws the pairs of `genes=("v_call", "j_call")` counted without groups, each locus's `max_genes` (20) V genes against its `max_genes` J genes, those with the most chains; `ds.plots.spectratype` draws each group's length distribution as a line in the group's colour, or bars for one group, one panel per locus, with one legend of the first 80 groups beside the first row. An axis that leaves genes out says how many of how many it draws, such as "V gene (30 of 52)". The heatmaps of every locus share one colour bar, from 0 to the largest fraction drawn, and stand two to a row; bars and lines stand three to a row. A figure whose chains have none of the counted values is refused. Counted with `count="clonotypes"`, the figures name what they count as `ds.plots.clone_abundance` does: clonotypes, or clonotype clusters for clonotypes that a distance metric linked.

Each distinct gene call is decoded and named once, and each distinct junction is measured once from its packed bytes, a stored chunk at a time, without being decoded into text. The memory budget must allow, at each step, what the step holds beside the earlier ones: the chain slots of every cell and each contig's codes of the fields counted, read whole; the grouping of the cells, which counts as the clone summaries' grouping does; each counted chain with its fields; the distinct values that the chains name; and the table, with a row for each group, locus and value. A refusal names the step, and from the counted chains on, a smaller `cell_selection` or fewer slots as well as a larger budget ([what a refusal names](../concepts/memory-and-execution)).

On "Human PBMC from a Healthy Donor, 10k cells (v2)" with the TCR and BCR files imported together, the counts of every V gene, J gene and V-J pair of the `VJ_1` and `VDJ_1` slots, and of every junction length in residues and nucleotides, equal scirpy 0.25.1's `group_abundance` of the slot's calls and its `spectratype` for each of four pseudo samples drawn from a hash of each barcode: 95 VJ and 85 VDJ V genes, 61 and 19 J genes, 1,651 and 658 V-J pairs, and 16 and 22 lengths. scRepertoire's `percentGenes` and `percentAA` parse its concatenated clone strings through immApex rather than counting chains; its gene shares of a pseudo sample divide by 1,179 cells, which neither the cells with a beta chain (1,322) nor those with both chains (1,185) reproduce, so they serve as no reference here. On a million simulated T cells in eight samples, on one thread, `gene_usage` by sample takes 0.8 s, V-J pairs 0.8 s, V-J pairs counted once per clonotype 1.0 s, and `spectratype` 1.3 s.

## Export AIRR Rearrangement files

The AIRR Community's Rearrangement TSV is what Immcantation (Change-O, SHazaM, dowser), dandelion and scirpy read, so `export_airr` carries a CyteArc analysis to the analyses CyteArc leaves to them, such as B cell lineage trees and somatic hypermutation, which need IMGT-gapped alignments that those tools compute:

```python
ds.repertoire.export_airr(clonotypes, "repertoire.tsv.gz")  # contigs with clone_id
ds.repertoire.export_airr(receptors, "chains.tsv", chains_only=True, fields=["v_call", "j_call", "junction"])
```

Each row is one contig of the receptors: `cell_id`, the cell's ID in this store, which matches the expression data, and the fields that the receptors store, all of them by default or those of `fields`. With a `clonotypes` artifact as the source, `clone_id` holds each cell's clonotype label, empty for a cell without one, in place of any imported `clone_id`. The schema's required fields come first, in its order, empty when the receptors do not store them, as for a Cell Ranger CSV's sequences, alignments and `rev_comp`; then `cell_id`, `clone_id`, `locus`, `c_call` and `umi_count`, then the other fields. Logical fields are written `T` and `F`, and a number field whose written values are all whole numbers, as AIRR's counts are, is written as integers. Every other value is written as it is, unquoted, as the AIRR file format asks. The format forbids tabs and newlines in values, which would end a field or a row, and readers take a carriage return for the end of a row too, so a value that holds any of the three raises `ValueError` before the file is opened, naming each field that holds one, how many of its values do and the `sequence_id` of the first contig whose value does; `fields` can leave such a field out, except the columns that are always written. The format advises against `@`, `#`, `"` and `'`, since readers may take them differently, so the export warns with the number of values that hold them and their fields; a value that starts with a double quote, in any field, has a warning of its own, since the readers described below take it for an opening quote and can join or drop rows without an error. The schema requires unique `sequence_id`s, so an ID that repeats, such as `<barcode>_contig_1` in the TCR and the BCR file of one cell, gets `_2`, `_3` and so on from its second occurrence, with a warning. The export returns an {class}`~cytearc.ExportSummary`: the file, its `rows`, the contigs written, and its `diagnostics`, `contigs`, `renamedContigIds`, `leadingQuoteValues` and `discouragedValues`, the values that start with a double quote and those that hold another character that the format advises against, and `leadingQuoteFields` and `discouragedFields`, their fields as the warnings name them, from which each warning comes as a `DiagnosticWarning`. `chains_only=True` leaves out the contigs that do not count as chains. A path ending in `.gz` is gzip-compressed at level 6, with a header that names no file and no time, so the same contigs give the same bytes. `cytearc.writers.write_airr_rearrangements` writes any table of contigs whose `sequence_id`s are unique, and `cytearc.writers.airr.AirrRearrangementWriter` writes a file one block of contigs at a time.

The export streams the stored contigs instead of loading them into a table: it copies the stored bytes of the text fields into the rows without decoding them, and holds, beside one block of contigs, each cell's ID and clonotype label as packed bytes and the distinct values of the text fields. A first pass hashes every `sequence_id`, and only the IDs whose 64-bit hashes repeat are read as text to choose their suffixes. Every stored array is read a chunk at a time, and each step is charged before it runs, all before the file is written ([what a refusal names](../concepts/memory-and-execution)). What the export holds grows with the cells, whose IDs and clonotype labels it packs, the contigs, whose `sequence_id` it hashes at 8 bytes each, and the distinct values of the text fields, beside one block of contigs, about 32 MiB and at most a sixteenth of the memory budget, of as many contigs as fit when each field holds its longest value.

Exporting the contigs of "Human PBMC from a Healthy Donor, 10k cells (v2)", TCR and BCR together, gives a file that the AIRR Community's `airr` 2.0.0 library validates and reads with `read_rearrangement`, and that scirpy 0.25.1's `read_airr` reads into the same 6,189 cells, with the same receptor type, subtype and chain pairing and the same junction, V and J calls in every slot, as its `read_10x_vdj` reads from Cell Ranger's files. Importing the exported file into CyteArc again gives the same 41 per-cell columns and the same clonotypes, and every exported `clone_id` is its cell's clonotype. Cell Ranger's CSVs hold no `rev_comp`, so the export leaves it empty, as the airr library's own writer leaves a missing value; the library's `load_rearrangement` reads logical columns as booleans that cannot be missing and refuses such a file, so read it with `read_rearrangement` or with pandas.

Read the file without quoting, as the format writes it: pandas reads every value as it was written with `dtype=str, keep_default_na=False, quoting=csv.QUOTE_NONE`, as CyteArc's import reads AIRR files. The airr library's `read_rearrangement` 2.0.0, which scirpy 0.25.1's `read_airr` reads through, and pandas by default read `@`, `#`, `'` and a double quote within or at the end of a value as written. They take a double quote at the start of a value, a Phred score's too, for the start of a quoted field, which runs on to the next double quote anywhere in the file: the quotes around a value are dropped, and otherwise the fields and rows up to that quote join the value. Both refuse the file when the joined row holds more fields than the header, the airr library with "row has extra data", and pandas refuses a quote that never closes, which the airr library reads to the end of the file; any other rows that join are lost without an error, and the airr library still validates the file. So a value that starts with a double quote is the one to avoid in a file that other tools will read.

On one thread, the export of 200,000 simulated T cells, whose 372,948 contigs were imported from a Cell Ranger CSV, writes a 59 MB file in 0.9 s, or 1.9 s when it first compiles its kernels, and that of 100,000 simulated B cells, whose 199,975 contigs were imported from an AIRR file with full sequences and alignments, a 325 MB file in 2.0 to 2.3 s, about 0.6 s of which go to checking each byte of their 300 MB of sequences and alignments before the file is opened. Compression takes most of a `.gz` export's time where the text compresses poorly: the B cells' file takes 34 to 35 s at level 6.
