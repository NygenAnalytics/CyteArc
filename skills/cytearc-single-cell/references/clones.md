# Clones and lineage tracing

Import the clones that a lineage tracing tool or a study assigned to cells, the lineage barcodes that clones are called from and call the clones, or the alleles of a lineage recorder that trees are built from and clones are called from, join them to the store's cells, check how many barcodes joined, see how large the clones are, measure clonal expansion and diversity within samples or other groups of cells, compare groups by the clones they share, measure which fates are coupled, and follow the clones of early cells to the fates they took. Docs: <https://docs.nygen.io/CyteArc/api/clones.html>, <https://docs.nygen.io/CyteArc/analysis_with_agents.html>.

## When to use

- A file that lists each cell's clone: CoSpar's `Cell_ID,Clone_ID` table, TREX's `clones.txt`, CellTag-multi's or CellTagR's clone table, STICR's Cell Browser `meta.tsv`, Cassiopeia's allele table (`lineageGrp`), Numbat's `clone_post_{i}.tsv`, LARRY's GEO clone matrix with its metadata, an AnnData file with CoSpar's `obsm['X_clone']` or MiTo's `obs['MiTo_clone']`, or any table with a cell and a clone column.
- A cell metadata column that already holds each cell's clone: `ds.clones.from_column`.
- Immune receptor clonotypes from `ds.repertoire.clonotypes` (see `immune-repertoires.md`): every function below takes a `clonotypes` artifact as it takes `clones`.
- A file that lists barcodes per read, molecule or cell without clone IDs (TREX `molecules.txt`, pycashier, CellTag-multi's per-read tables, FateMap, QuiCAT, BARtab counts, Cell Ranger `molecule_info.h5`), or an assay of barcode counts: `ds.clones.import_barcodes`, which keeps every molecule and barcode for clone calling.
- Clones from imported lineage barcodes: `ds.clones.barcode_clones` with the preset of the method that made them (LARRY, TREX, CellTagR, CellTag-multi) or rules chosen one by one.
- The edits of a lineage recorder per cell and array: DARLIN's or CARLIN's `AlleleAnnotations.txt` and `AlleleColonies.txt`, the `darlin` CLI's `step4_final.tsv`, Cassiopeia's allele tables (before 3.0, or 3.0's parquet), PEtracer's allele tables and character matrices, DNA Typewriter's tables, a TreeData file's `obsm['characters']`, another tool's character matrix, or any table of alleles: `ds.clones.import_alleles`, then `ds.clones.export_characters` for Cassiopeia or LAML, which build the trees. CyteArc builds no trees.
- Clones from imported recorder alleles, cells that share a rare allele: `ds.clones.allele_clones` by DARLIN's frequency graph or CARLIN's p_clonal test, with each array's allele bank.
- A lineage recorder's trees whose leaves are cells (PEtracer, DNA Typewriter, Cassiopeia, LAML, ConvexML): Newick text or TreeData `.h5td`/`.zarr`, imported with `ds.clones.import_phylogeny` and cut into clones with `ds.clones.phylogeny_clones`. CyteArc never reconstructs trees.

## Key concepts

- `ds.clones.import_clones(paths, *, cell_selection, barcode_prefix=None, barcode_suffix=None, barcode_pattern=None, format=None, columns=None, multiple="error", invalidate_cache=False)` saves a datastore-scoped `clones` artifact. The format comes from the file: HDF5 is AnnData, `%%MatrixMarket` a clone matrix, and a text header names the tool. `format` is one of `"cospar"`, `"trex"`, `"celltag_multi"`, `"celltagr"`, `"sticr"`, `"cassiopeia"`, `"numbat"`, `"table"`, `"matrix"`, `"cospar_h5ad"`, `"mito"`, `"h5ad"`.
- `columns={"cell": ..., "clone": ..., "probability": ...}` reads any other table (format `"table"`) or an AnnData `obs` column (`"h5ad"`, clone and probability only). `"cell"` may list columns joined by `"__"`, as LARRY's `["Library", "Cell barcode"]`. A table with R row names (header one field shorter than its rows, such as the Biddy workflow's `celltag_data.txt`, or a first column with an empty name, as `write.csv` writes) takes cells from the row names, so `columns={"clone": "CellTagD13"}` reads one labelling round. Blank lines hold no rows. A table whose every row ends in its delimiter, one field more than its header with nothing in the last, is refused, since R's row names with an empty last column read alike; end the header with the delimiter too, or write the row names under a header name (`write.table(..., col.names=NA)`).
- A clone matrix reads its cell list beside it: `<name>metadata.txt.gz` beside `<name>clone_matrix.mtx.gz` (LARRY on GEO), or `cells.tsv` with `clones.tsv` (the export). The axis whose length equals the cell list holds the cells, so LARRY's in vitro (cells by clones) and in vivo and cytokine (clones by cells) files read alike. Unnamed clones are labelled by position from 0.
- The join: a cell's ID is `barcode_prefix + barcode + barcode_suffix`; `barcode_pattern` keeps the named group `barcode` of each barcode (`re.search`), and a barcode it does not match joins no cell. Each option takes one value for every file or one per file. A merged store names cells `<sample>__<barcode>`, so a sample's 10x file needs `barcode_prefix="<sample>__"`, and a TREX file of bare barcodes also `barcode_suffix="-1"`.
- Check the join in `ds.artifacts.inspect(ref).diagnostics`: `fileBarcodes` counts the files' barcodes by the cell ID they name, `unmatchedBarcodes` those that name no cell of the store, which a `DiagnosticWarning` names up to five of (again on reuse), and `unselectedBarcodes` those of store cells outside `cell_selection`, which give no warning; `unmatchedBarcodeExamples` and `unselectedBarcodeExamples` show up to five as `"barcode -> cell ID"`. Many unmatched barcodes mean a wrong prefix, suffix or pattern or a file of another run; many unselected ones, a selection that left out cells, as QC filtering does. Non-cell droplets in a file are expected to be unmatched.
- Several files: each file's clone labels start with its `barcode_prefix`, or with its name before the first `.` and `_`, because clone IDs are unique only within one run (TREX numbers clones from 1 in every run). Two files with one namespace, such as two `clones.txt` without prefixes, raise `ValueError`.
- A cell in two different clones raises `ValueError` naming examples; `multiple="drop"` leaves such cells without a clone and counts them in `n_cells_in_several_clones`. Repeated rows of one cell and clone (Cassiopeia lists a cell per target site) count once. Cassiopeia's lineage group 0, MiTo's `"unassigned"`, and empty labels or text that every table reads as missing, such as `NA`, `NaN`, `None`, `NULL` or `N/A`, mean no clone; `export_clones` refuses such labels in CoSpar's table and keeps them in a matrix. A table's row of fewer or more fields than its header, and a cell joined from several columns with one empty, are refused naming the line.
- The file's bytes identify it: a moved file reuses the saved clones, an edited one gives new ones, and the order of files does not matter. `invalidate_cache=True` imports again.
- `ds.clones.from_column(column, *, cell_selection, invalidate_cache=False)` saves the clones of a cell metadata column; missing or blank labels mean no clone, and float whole numbers read as integers.
- Memory: the store keeps each cell's label at the width of the longest, so very long labels cost memory for every cell; an import that would not fit `mem_budget` raises `MemoryError` before saving.
- The artifact: canonical `values` (clone label, empty for none), `codes` (clones by size, largest first, then label; -1 for none), `clone_size` (0 for none), and `clone_probability` where the source gives one (Numbat's `p_opt`, or `columns["probability"]`). `ds.select_cells(clones, include=["3"])` selects one clone's cells, and `ds.artifacts.load_values(clones, value="clone_size")` reads the sizes.
- `ds.clones.load_clones(clones)` returns a `Clones` record: `.cells` (indexed by cell ID: `clone` categorical in rank order, `clone_size`, `clone_probability` when stored), `.clones` (`clone`, `n_cells`, largest first), `.source`, the operation that saved them (`"import_clones"`, `"import_clones_from_column"`, `"define_clonotypes"`, or a caller's, such as `"call_barcode_clones"`) and `.kept_apart`, the columns of `.cells` whose labels the clones keep apart: `()` for clones, `("receptor_type",)` for clonotypes, whose `.cells` then holds each cell's receptor type.
- `ds.clones.export_clones(clones, path, format="cospar")` writes CoSpar's `Cell_ID,Clone_ID` CSV, which imports back as `format="cospar"`; `format="matrix"` writes a cells by clones Matrix Market file with `cells.tsv` and `clones.tsv` beside it, replacing files of those names. Both import back to the same clones; probabilities are not written. The table refuses labels that read as no clone, such as `NA` from `from_column`, and the matrix refuses labels with line breaks: use the other format. Returns the cells written.
- `ds.plots.clone_abundance(clones, group_by=None, groups=None, max_clones=20)` draws clones per clone size on log scales and the largest clones; with a grouping, one line per group and each clone's cells stacked by group. `group_by` takes one column or several and `groups` a label artifact, alone or together, grouped as every clone summary groups cells (`"d2, Monocyte"`). The largest clones are labelled by ID, clonotypes by their representative's junction (`CASSLGQAYEQYF`; `VJ_1` first for `receptor_arms="VJ"`) and also by their number where two drawn share one (`CAVA 1`, `CAVA 3`); for a clonotypes artifact the title reads `Largest 20 clonotypes`, and `Largest 20 clonotype clusters` when a `metric` other than `"identity"` defined it. Tables: `sizes` (`group`, `clone_size`, `n_clones`) and `top`, one row per clone drawn and group, zeros included (`clone`, `label`, `group`, `n_cells`; `"all cells"` without a grouping), so a group may take any name.
- `ds.clones.import_barcodes(paths=None, *, cell_selection, from_assay=None, barcode_prefix=None, barcode_suffix=None, barcode_pattern=None, format=None, columns=None, library=None, invalidate_cache=False)` saves a datastore-scoped `lineage_barcodes` artifact (operation `import_lineage_barcodes`). `format` is one of `"trex"` (`molecules.txt`, `molecules_corrected.txt`, every release), `"pycashier"` (with or without header), `"celltag"` (CellTag-multi per-read, ATAC without `UMI`; Biddy parsed reads), `"fatemap"` (with or without header; one sample per file), `"quicat"`, `"quicat_wide"`, `"h5ad"` (cells by barcodes in `X`), `"bartab"`, `"bartab_annotation"` (`;` or legacy `,` lists), `"molecule_info"` (Cell Ranger, one feature barcode library; `library` names its type when several), or `"reads"`, `"molecules"`, `"pairs"` with `columns`. Detected from the header otherwise; TREX's `reads.txt` is refused; clone tables point to `import_clones`.
- Levels: read rows collapse into molecules (reads = rows), or into pairs without UMIs (CellTag ATAC, TREX Smart-seq2); molecule rows keep their reads or -1; pairs keep UMIs and reads, -1 where unknown. Nothing is filtered: errors, one-read molecules and ambient barcodes stay for clone calling. QuiCAT, BARtab, h5ad and `from_assay` counts are read as UMIs; a QuiCAT table of reads needs `format="pairs"` with `columns={..., "reads": "counts"}` (`{"reads": "X"}` for h5ad).
- `columns` roles: `"cell"`, `"barcode"` (one column, or several joined by `"__"`, such as CloneTracker XP's two halves), `"umi"` (molecules need it), `"umis"`, `"reads"`, `"library"`, `"separator"` (`;`, `,`, `:` or `|`; splits a pair's barcode and count lists, kept aligned). Without `"cell"`, R row names are the cells (Watermelon's metadata).
- Libraries: `library` names each file's library (one for every file or one per file; default the file's name before its first `.`; the assay's name with `from_assay`). A library holds molecules or pairs, never both; rows of one library naming one molecule merge, summing reads. Use `library=["RNA", "ATAC"]` for CellTag-multi's two modalities.
- Barcode artifact: canonical `n_barcodes` (distinct barcodes per cell), `n_umis`, `n_reads` (-1 where a library counts none), `n_records`; `record_*` arrays hold one row per molecule or pair. Attributes `libraries` (`library`, `level`, `records`, `has_umis`, `has_reads`), `n_file_rows`, `n_unmatched_rows` (rows read: one per list item, or per nonzero count of a merged table or matrix), `n_empty_rows` (no barcode, or a pair counted 0); diagnostics: the join's.
- `ds.clones.load_barcodes(barcodes)` returns a `LineageBarcodes` record: `.cells` (indexed by cell ID), `.records` (`ids`, the cell, `library`, `barcode`, `umi` categoricals, `umi` missing for pairs; `umis`, `reads` nullable `Int64`; a molecule's `umis` is 1), `.libraries` (`library`, `level`, `n_records`, `has_umis`, `has_reads`), and `.pairs()` (one row per cell, library and barcode: `ids`, `library`, `barcode`, distinct `umis`, `reads`, `n_molecules`).
- `ds.clones.barcode_clones(barcodes, *, preset=None, min_reads=None, max_distance=None, metric=None, allowlist=None, min_umis=None, min_fraction=None, barcodes_per_cell=None, method=None, similarity=None, inclusive=None, prune=None, doublets=None, min_size=None, trex_rules=None, within=None, invalidate_cache=False)` saves a `clones` artifact (operation `call_barcode_clones`). `within` names one cell metadata column or several, such as the mouse, whose labels keep clones apart; every cell with a barcode needs a label, and the labels join no table, so any column name works. Rules in order: molecules below `min_reads` dropped; within each `within` group and library, barcodes within `max_distance` by `metric` (`"hamming"`, `"levenshtein"`) merge into the most abundant of their connected component (ties to the barcode that sorts last); barcodes outside `allowlist` (a sequence of text) dropped; per library, a cell's barcodes below `min_umis` UMIs, or whose UMIs divided by `min_fraction` stay below its top barcode's (BARtab), dropped; cells outside `barcodes_per_cell=(fewest, most)` get no clone; then `method="sets"` (identical barcode sets) or `"jaccard"` (identical sets as nodes, edges between nodes sharing a barcode whose Jaccard index exceeds `similarity`, or reaches it with `inclusive=True`; `similarity=(within_libraries, across_libraries)` for two modalities; `prune` and `doublets` are TREX's bridge and local-cut-vertex rules); connected components are clones; clones below `min_size` cells leave their cells without one.
- Presets: `"larry"` (`min_reads=10`, Hamming 3, `min_umis=3`, sets), `"trex"` (TREX's partial-cloneID rules: entropy below 1 bit dropped, Hamming 5 over the positions both hold a base with at least 20, 20 bases kept, one-UMI cloneIDs shared with other cells or of one read dropped; Jaccard above 0.7, prune, doublets, singletons kept), `"celltag"` (allowlist, `min_umis=2`, 2 to 20 tags, Jaccard above 0.7, clones of 3 or more), `"celltag_multi"` (`min_reads=2`, Levenshtein 2, allowlist, `min_umis=2` (reads for scATAC-seq), 2 to 25 tags, Jaccard above 0.6 within a library and 0.5 across, clones of 2 or more). An argument replaces its preset's value; 0 turns a count filter off. `trex_rules` follows the preset (on for `"trex"`) unless given: `trex_rules=False` calls `"trex"` without TREX's cloneID rules, `True` adds them to other rules. `cytearc.clones.BARCODE_PRESETS` holds each preset's values, read-only; the artifact's provenance records the resolved rules. The CellTag presets require `allowlist`; `allowlist=False` calls them without. Without a preset, `method` is required, `"jaccard"` needs `similarity` and `inclusive`, and `max_distance` needs `metric`.
- Counts are read in each library's unit: a molecule is one UMI; a pair counts UMIs, or reads in a library with no UMIs for any pair (CellTag-multi scATAC-seq). A library with UMIs for some pairs only has no unit. Rules refuse counts they cannot read: `min_reads` needs every molecule's reads (pairs pass it; all-pair barcodes are refused), correction and pair filters a unit per library, TREX's rules molecules with reads (TREX writes `read_count` since 2024-09). `method="sets"` alone reads no count.
- Barcode clones: labels `clone_1` (largest) on; arrays `n_barcodes` (after pair filters) and `doublet`; attributes `rule_counts` (what each rule removed or changed: `molecules_below_min_reads`, `barcodes_corrected`, `records_outside_allowlist`, `pairs_below_min_umis`, `cells_outside_barcodes_per_cell`, `nodes`, `edges`, `edges_pruned`, `doublets`, `cells_in_small_clones` and TREX's), `library_units` and `diagnostics`: `distinctBarcodes` (compared after the molecule filters, per `within` group and library; TREX's cloneIDs under 20 bases excluded), `expectedChanceMatches` (pairs of them within `max_distance` by chance, from each position's base frequencies among them: exact under that independence for Hamming, an approximation for Levenshtein), `mergedBarcodes` (equals `barcodes_corrected`), `largestCloneShare` (largest clone's cells over `cellsWithClone`, the cells given a clone, 0 without clones; every source's clones record both); 0 expected and merged at `max_distance=0`. `load_clones(...).diagnostics` returns them as a dict, as `ds.artifacts.inspect(clones).diagnostics` does. `metric="levenshtein"` takes `max_distance` at most 8. `load_clones(...).cells` gains `n_barcodes` and `doublet`; `.source` is `"call_barcode_clones"`. Every summary reads the artifact as it reads imported clones.
- `ds.plots.barcode_calls(barcodes, max_barcodes_per_cell=10)` draws cells by barcodes per cell, pairs by UMIs per barcode and molecules by reads per molecule, per library, under one legend of the libraries; a panel that no library fills says so. Tables: `barcodes_per_cell` (`n_barcodes`, `n_cells`), `umis_per_barcode` (`library`, `umis`, `n_pairs`), `reads_per_molecule` (`library`, `reads`, `n_molecules`).
- Recorder model: an integration is one copy of a target array, named as its tool names it (a DARLIN array `CA`, `TA` or `RA`, Cassiopeia's `intBC`, PEtracer's `intID`, DNA Typewriter's `TargetBC`). Sites are `independent` (PEtracer's `RNF2`, `HEK3` and `EMX1`, each with a lookup of eight marks; the columns of a character matrix), `ordered` (DNA Typewriter's slots, edited in turn) or `indel` (a CARLIN or DARLIN allele over its whole array, one site of no name; Cassiopeia's cut sites). Each site of a cell is `unedited`, `mark`, `unknown_mark` (an edit no lookup names, written as its sequence, or a placeholder such as PEtracer's `!` or CARLIN's `X`, whose `allele` is missing because it names none), `missing` (not read, or an insertion with an ambiguous `N`) or `not_applicable` (a slot beyond a contracted tape, an integration the cell's embryo lacks). Ordered slots follow the prefix rule: a blank slot before an edit is missing, and a slot at or beyond its integration's length is not applicable; an insertion there is counted in `n_beyond_length` and warned about.
- `ds.clones.import_alleles(paths, *, cell_selection, format=None, integrations=None, barcode_prefix=None, barcode_suffix=None, barcode_pattern=None, columns=None, invalidate_cache=False)` saves a datastore-scoped `lineage_alleles` artifact (operation `import_recorder_alleles`). Each file's format is recognised from its contents unless `format` names one of `"carlin"`, `"darlin"`, `"cassiopeia"`, `"cassiopeia_parquet"`, `"petracer"`, `"petracer_characters"`, `"typewriter"`, `"typewriter_chains"`, `"treedata"`, `"laml"` (LAML's character matrix, or another tool's in its layout) or `"table"`. Each format's tokens set the state: Cassiopeia's `None` is uncut, PEtracer's `None` unedited, a blank DNA Typewriter slot unedited after the last edit; a token the format does not write is refused with its lines, and a CARLIN bulk run, which lists UMIs, is refused. Cassiopeia 3.0's parquet sites follow the edit models its `attrs` record (indels, PEtracer's lookup insertions, tape slots); a TreeData array is read only where `uns['embryo_characters']` names its columns, as PEtracer's files do. A file of a header alone adds no records. Tables other than DNA Typewriter's of 2022, which is read by position, read R's row names as clone tables do, and refuse rows that all end in their delimiter; a character matrix whose header leaves out the cells' column takes R's row names even where every row ends in an empty state. The join, its attributes and reuse by file bytes work as for clones.
- `integrations`: a CARLIN pair or `darlin` table holds one array without naming it, so `integrations="CA"`, or one name per file, names it; it is never inferred. For DNA Typewriter, map each tape shorter than the recorder's arrays to its slots, such as `{"TGGACGAC": 4, "TTTCGTGA": 4, "TGGTTTTG": 4, "TTCACGTA": 2}` for the HEK293T line of 2022; a tape no row or column names is refused. Files of different arrays with the same prefix, suffix and pattern are one library and must share cells. Rows that name no integration, such as PEtracer's empty `intID`, are left out, counted in `n_rows_without_integration` and warned about.
- `columns` for `format="table"`: `"cell"`, `"integration"` (or `integrations` names the one), the sites as `"sites"` (a column per site) or `"allele"` with `"site"` (one site per row) or `"separator"` (sites joined in one field, numbered from 1), `"umis"`, `"reads"`, `"kind"` (`"indel"` by default, `"independent"` or `"ordered"`), `"slots"`, and the tokens `"unedited"`, `"missing"`, `"not_applicable"` and `"unknown"` (placeholders that name no allele). A separator splits every row into the sites of the file's first allele; ordered slots need `"slots"`. Only here is text that pandas reads as missing, such as `NA` or an empty field, missing.
- Allele artifact: canonical `n_edits` (sites with a mark or an unknown mark, so `ds.select_cells(alleles, low=0)` keeps cells with an edit), `n_integrations` (integrations with a site read) and `n_records`; `record_*` arrays hold one row per cell, integration, site and allele row, several alleles of one cell and integration kept. Attributes `files` (each file's `format`, `tool`, `pipeline`, `kind`, `integration`, `lengths`, `rows`, `records`), `n_file_rows`, `n_unmatched_rows`, `n_beyond_length`, `n_rows_without_integration`; diagnostics: the join's.
- `ds.clones.load_alleles(alleles)` returns a `LineageAlleles` record: `.cells` (indexed by cell ID: `n_edits`, `n_integrations`, `n_records`), `.records` (`ids`, the cell, `file`, `integration`, `site`, `state`, `allele` categoricals, `allele` missing for states other than marks; `umis`, `reads` nullable `Int64`; `row`, the line in its file), `.files` (with `n_rows` and `n_records`), and `.site_states()` (`integration`, `site`, `state`, `n_cells`).
- `ds.clones.export_characters(alleles, path, *, format="treedata", unknown="state")` writes one column per site, named `{integration}-{site}` (or the integration for an allele of no site name), and returns the cells written. States: 0 unedited, missing for missing and not applicable, a whole-number mark without leading zeros (PEtracer's `1` to `8`, a matrix's state) as itself, other marks by text and then unknown marks that name their allele after the largest such number; placeholders (`!`, `X`) are missing, so cells holding them share no state; `unknown="missing"` writes every unknown mark as missing. Of several allele rows of one cell and integration, the one of most UMIs, then reads, then sites read is written, with a warning. Cells and characters with nothing read are left out. `"treedata"` creates a TreeData `.zarr` store, which Cassiopeia 3.0 reads (`obsm['characters']` int64, `uns['missing_state']` -1, `uns['unmodified_state']` 0, `uns['character_states']`); `"laml"` writes `cell,<characters>` rows with `?` for missing, `<stem>_priors.csv` (headerless character position from 0, state, probability) and `<stem>_states.csv` (each state's `character`, `state`, `allele`, `kind`, `n_cells`). Each export imports back with its own token, `"treedata"` or `"laml"`.
- `ds.plots.recorder_states(alleles, max_sites=40)` draws one bar per site stacked by the fraction of its cells with a mark (on top), an unknown mark, an unedited site or no read, leaving out cells whose integration lacks the site; with more sites, the `max_sites` read in the most cells, as the title says. Alleles without a record raise `ValueError`. Table: `site_states` (`integration`, `site`, `state`, `n_cells`, `share`).
- `ds.clones.allele_clones(alleles, *, method, frequencies=None, max_frequency=None, max_samples=None, max_alleles=None, fdr=0.05, within=None, invalidate_cache=False)` saves a datastore-scoped `clones` artifact (operation `call_allele_clones`). An allele is one character's mark or named unknown mark (`23_268del,55_248del` on DARLIN's `CA`); unedited sites, placeholders (`X`, `!`) and missing sites never link. `method="graph"` (DARLIN): rare when frequency `<= max_frequency` and bank `sample_count <= max_samples`; needs one of them; DARLIN's "below 2e-5" is `max_frequency=float(np.nextafter(2e-5, 0))`. `method="p_clonal"` (CARLIN): p = (1 - e^-x - x e^-x) / (1 - e^-x), x = rate × the group's cells with an edit at the character, Benjamini-Hochberg at `fdr` per `within` group over every array's alleles; needs a bank; refuses `max_frequency`; p grows with the cells (rate 1e-6 among 1e6 cells: 0.42), so in large experiments only alleles missing from the bank (rate 0) survive. Cells sharing a rare allele at any character are linked and components are clones; `max_alleles` drops clones of more distinct rare alleles (DARLIN: 3). `frequencies`: `{character: DataFrame}` keyed by integration (or `{integration}-{site}`), columns `allele`, `normalized_count` (share of the bank's edited observations), optional `sample_count`, as DARLIN's banks hold them (`pd.read_csv("allele_bank_Gr_CA.csv.gz")`); every character with alleles needs one; alleles missing from a bank are rare (frequency and rate 0). Without a bank, frequency is the allele's share of its group's cells edited at the character, inflated by clonal expansion.
- Allele clones: labels `clone_1` (largest) on; array `n_alleles` (each cell's distinct rare alleles); attributes `rule_counts` (`alleles`, `alleles_too_frequent`, `alleles_not_significant`, `alleles_in_too_many_samples`, `rare_alleles`, `cells_with_rare_alleles`, `clones_with_too_many_alleles`, `cells_in_clones_with_too_many_alleles`) and `bank_coverage` (per character with a bank: `alleles`, `alleles_in_bank`, `observations`, `observations_in_bank`). Reuse follows the rules, the banks' content in any row order and the `within` labels; `fdr` is recorded for p_clonal only.
- Summaries take `clones, *, group_by=None, groups=None, cell_selection=None` and count each clone's cells within groups: the combinations of the `group_by` columns' labels and the `groups` label artifact's (key column named by its kind, such as `cluster_labels`). Cells without a clone or a label count in no group, and when no cell has both, every summary raises `ValueError`. Clonotypes keep each receptor type apart: `receptor_type` joins the key columns, so a sample's T cells and B cells are two groups (`"s1, TCR"`, `"s1, BCR"`), and the groups without a grouping are the receptor types; `group_by="receptor_type"` is refused. The abundance plot groups clonotypes alike. A group is named by its labels joined by `", "`, or `"all cells"`, in each table's `group` column; each record's `.group_keys` holds the labels, one row per group indexed by `group` (by `fate` in fate bias), a column per key column under its own name (`group_by` columns, the `groups` kind, then `receptor_type` for clonotypes). A grouping may name any column, even one named like a table's column; join with `record.indices.join(record.group_keys, on="group")`, adding `rsuffix="_label"` when a key column shares a table column's name; a key column named `group` (or `fate`) also shares the index's name, so `rename_axis("group_name")` before `reset_index`, `merge`, `sort_values` or `groupby`. Labels with commas that give two groups one name, and a key column named twice, raise `ValueError`.
- `ds.clones.expansion(clones, group_by=None, groups=None, cell_selection=None, breakpoints=None, frequency_breakpoints=None, invalidate_cache=False)` saves a datastore-scoped `clonal_expansion` artifact (operation `measure_clonal_expansion`) of the cells of `cell_selection`, or of the clones' cells; a selected cell the clones do not hold has no clone. Pass at most one bound: `breakpoints`, default `(1, 2, 5, 20, 100)`, gives `"1 cell"`, `"2 cells"`, `"3 to 5 cells"`, `"6 to 20 cells"`, `"21 to 100 cells"`, `"more than 100 cells"` (scirpy's `clonal_expansion`); `frequency_breakpoints` (bins `(lower, upper]` ending at 1, such as scRepertoire's `(0.0001, 0.001, 0.01, 0.1, 1)`) bins each clone's share of its group's cells with a clone.
- Expansion arrays: canonical `values` (category, empty without a clone or group), `group_clone_size`, `group_clone_frequency`, `group_codes`. `select_cells(expansion, include=["21 to 100 cells", "more than 100 cells"])` keeps the cells of large clones. Reuse follows the clones, cells, label artifact, bounds and each cell's `group_by` labels. Every summary checks the memory budget before it reads: about 300 bytes per cell to measure expansion and 500 to load it beside the cells' IDs as text, 100 per cell to group plus three times the stored width of each `group_by` column's labels, and 2,000 per group, so a label for each cell costs far more than the cells; the clones API page lists every step.
- `ds.clones.load_expansion(expansion, splits=(10, 100, 1000, 10000, 30000, 100000))` returns a `ClonalExpansion` record: `.cells` (`clone`, `category` (ordered), `group`, `group_clone_size`, `group_clone_frequency`; labels are categoricals), `.categories` (`group`, `category`, `n_cells`, `n_clones`, `fraction`; every category of every group), `.rank_windows` (`group`, `window` such as `"1 to 10"`, ..., `"after 100000"`, `n_cells`, `fraction`: scRepertoire's `clonalProportion`), `.group_keys`, `.labels`, `.breakpoints`, `.frequency_breakpoints`, `.splits`, `.group_by`, `.groups`, `.cell_selection`, `.clones`.
- `ds.plots.clonal_expansion(expansion, group_by=None, groups=None, count="cells", normalize=True, splits=...)` draws stacked bars per group of the categories (cells, or `count="clones"`) and of the rank windows. Groups default to the expansion's own; `group_by` (one column or several) and `groups` regroup the cells (categories stay those measured within the expansion's groups; ranks are recounted within the plotted groups, and clonotypes' receptor types stay apart, as in `"blood, TCR"`). Tables: `categories` (`group`, `category`, `n_cells` or `n_clones`, `fraction`), `rank_windows` (`group`, `window`, `n_cells`, `fraction`).
- `ds.clones.diversity(clones, group_by=None, groups=None, cell_selection=None, size=None, coverage=None)` returns a `ClonalDiversity` record and saves nothing: `.indices`, one row per group (`group`, `n_cells`, `n_clones`, `n_singletons`, `n_doubletons`, `coverage`, `shannon` in nats, `pielou`, `simpson`, `inverse_simpson`, `gini_simpson`, `gini`, `d50`, `chao1`, `chao1_bias_corrected`, `ace`), and `.hill`, one row per group and order 0, 1, 2 (`observed`, `estimated` asymptotic, `at_size`, `coverage_at_size`, `method_at_size`, `at_coverage`, `size_at_coverage`, `method_at_coverage`; methods `"rarefaction"`, `"observed"`, `"extrapolation"`), with `.group_keys`, `.size` and `.coverage`, by default iNEXT's smallest doubled size and lowest coverage at doubled sizes. `cytearc.clones.ORDERS` is `(0, 1, 2)`.
- `ds.clones.rarefaction(clones, group_by, groups, cell_selection, orders=(0, 1, 2), sizes=None, endpoint=None, knots=40)` returns a `Rarefaction` record: `.curves` (`group`, `order`, `size`, `method`, `diversity`, `coverage`) and `.group_keys`; default sizes are iNEXT's 40 knots per group (half up to its size, half to twice it); `sizes` gives every group the same sizes.
- Plots of summaries take the record the summary returns, so compute it once, read it, then draw it. `ds.plots.clonal_rarefaction(ds.clones.rarefaction(clones, group_by=...), base="size" or "coverage")`: one panel per order (`order_0`, `order_1`, `order_2`) plus `coverage` (sample completeness) with `base="size"`; solid rarefied, dashed extrapolated, a point at the observed size. Table: `curves`. `ds.plots.clonal_diversity(ds.clones.diversity(clones, group_by=...), indices=("n_clones", "shannon", "inverse_simpson"))`: one panel of bars per index across the groups (any `.indices` column); table `indices`.
- `ds.clones.overlap(clones, group_by=None, groups=None, cell_selection=None)` returns a `CloneOverlap` record and saves nothing; at least two groups must hold a cell with a clone. `.group_sizes`: `group`, `n_cells`, `n_clones`; `.group_keys`. `.pairs`, one row per pair of groups: `group_1`, `group_2`, `shared`, `jaccard`, `sorensen`, `overlap` (shared over the smaller group's clones), `cosine` (of presence), `morisita_horn`, `abundance_cosine` (of clone sizes), `shared_fraction_1`, `shared_fraction_2` (the share of each group's cells whose clone the other holds). `cytearc.clones.OVERLAP_INDICES` names the indices. Memory: about 250 bytes per pair of groups; `track` about 100 bytes per row.
- `ds.clones.track(clones, group_by, groups, cell_selection, top_n=10, labels=None)` returns a `CloneTracking` record: `.tracked` (labels, largest first) and `.table`, one row per chosen clone and group, zeros included: `clone`, `group`, `n_cells`, `fraction` (of the group's cells with a clone), and `.group_keys`. By default the union of each group's `top_n` largest clones (scRepertoire's `clonalCompare`; ties to the larger clone overall); `labels` names clones instead.
- `ds.plots.clone_overlap(ds.clones.overlap(clones, group_by=...), index="morisita_horn", color_scale=None)` draws one index as a heatmap of the pairs (pairs not compared in the missing colour; tables `matrix`, `pairs`); `ds.plots.clone_tracking(ds.clones.track(clones, group_by=..., top_n=10), order=None)` draws one line per tracked clone of its fraction of each group's cells, labelled as in `clone_abundance` (`order` may hold numbers, such as time points; the legend lists the largest first; table `tracking`, the record's `table` with `label`, the text drawn, beside `clone`, the ID that `track(labels=)` takes).
- `ds.clones.coupling(clones, *, group_by=None, groups=None, cell_selection=None, method="share_cosine", n_permutations=1000, random_seed=0)` returns a `CloneCoupling` record and saves nothing; at least two groups must hold a cell with a clone. `method` follows CoSpar's `fate_coupling` on a clone matrix: `"share_cosine"` (default; CoSpar's `"SW"` with `normalize=True`: cosine of each group's shares of each clone, every clone counted once), `"abundance_cosine"` (`"SW"`, `normalize=False`; overlap's index), `"normalized_covariance"` (`"Weinreb"`, `normalize=False`; below 0 when groups share fewer clones than chance), `"jaccard"`. `cytearc.clones.COUPLING_METHODS` names them. `.pairs`: `group_1`, `group_2`, `coupling`, `null_mean`, `null_sd`, `z_score`; the null shuffles group labels of the cells with a clone (keeps clone and group sizes), each permutation from a stream keyed by `random_seed`, so results do not depend on `nthreads`. `.group_sizes` (`group`, `n_cells`, `n_clones`), `.group_keys`, `.order` (average-linkage leaf order, most coupled together), `.linkage` (SciPy linkage of the `group_sizes` positions), `.method`, `.n_permutations`, `.random_seed`. `n_permutations=0` skips the null, and the heatmap of its z-scores is refused; 1 is refused. `random_seed` lies below 2**64. Memory: about 250 bytes per pair, 40 per product of two groups, and per thread 4 per cell with a clone and 8 per product of two groups; a tight budget runs the null on fewer threads.
- `ds.clones.fate_bias(clones, *, group_by=None, groups=None, early, late, invalidate_cache=False)` saves a datastore-scoped `clone_fate_bias` artifact (operation `measure_clone_fate_bias`) labelling the `early` cells (a cell selection) with their dominant fate; fates are the groups of the `late` cells (a cell selection sharing no cell with `early`). Per early cell: `values` (dominant fate, empty for none or a tie), `codes` (clone), `fate_codes`, `n_late_cells` (its clone's late cells), `fractions` (cells by fates, NaN without late cells; CoSpar's `fate_map(method="sum")` on its clonal transition map). Per clone with late cells: counts per fate and a one-sided Fisher test per fate against all late cells with a fate (CoSpar's `clonal_fate_bias(alternative="less")`, which is the upper tail), Benjamini-Hochberg within each fate (CoSpar adjusts within clone sizes). A fate may take any name.
- `ds.clones.load_fate_bias(bias)` returns a `CloneFateBias` record: `.cells` (indexed by early cell ID: `clone`, `n_late_cells`, `fate`), `.fractions` (indexed by early cell ID, one column per fate of its share, nothing else), `.clone_fates` (one row per clone with late cells and fate: `clone`, `fate`, `n_early_cells`, `n_late_cells`, `n_cells`, `fraction`, `p_value`, `q_value`), `.fates` (`fate`, `n_late_cells`), `.group_keys` (indexed by `fate`), `.clones`, `.early`, `.late`, `.group_by`, `.groups`. `ds.select_cells(bias, include=["Neutrophil"])` keeps early cells whose clones went mostly to neutrophils.
- `ds.plots.clone_coupling(coupling, value="z_score", color_scale=None)` draws the record as a heatmap in its linkage order with the tree above (z-scores centred on 0; `value="coupling"` for the values; tables `matrix`, `pairs`); `ds.plots.clone_fate_bias(bias, max_clones=40, normalize=False)` stacks the late cells of the `max_clones` clones with the most late cells by fate, grouped by dominant fate, under their early cells, labelled as in `clone_abundance` (tables `clones`, one row per clone drawn: `clone`, `label`, dominant `fate`, `n_early_cells`, `n_late_cells`; `fates`, one row per clone drawn and fate: `clone`, `label`, `fate`, `n_cells`).
- `ds.clones.import_phylogeny(paths, *, cell_selection, time_unit, format=None, barcode_prefix=None, barcode_suffix=None, barcode_pattern=None, invalidate_cache=False)` saves a datastore-scoped `cell_phylogeny` artifact. `time_unit` is required, never inferred: `"days"` for PEtracer and DNA Typewriter, or None for lengths that are not times (then cut by depth only). `format` is `"newick"` or `"treedata"`; a Zarr store or HDF5 file is TreeData. Newick: plain or gzip, several trees per file, comments, quoted labels, polytomies, single-child nodes, negative lengths and a root length are read; an unquoted number on an internal node is a support value, not a name (quote it, as `'95'`, to keep it); NEXUS is refused. TreeData: node `time` is preferred over edge `length`; other attributes are dropped; `.zarr` stores written before treedata 0.3.0 are refused.
- Leaves join to cells as clone files do (`barcode_prefix + leaf + barcode_suffix`, `barcode_pattern`). Diagnostics: the join's (`unmatchedBarcodes`, leaves naming no cell of the store, warned again on reuse; `unselectedBarcodes`, leaves of store cells outside the selection). Attributes: `n_cells_in_no_tree`, `n_cells_in_trees`, `n_trees`, `n_leaves`, `leaf_time_spread` (largest gap between a tree's earliest and latest leaf; 0 when ultrametric). Two leaves naming one cell, such as bootstrap replicates in one file, raise `ValueError`.
- Tree names: the file's prefix and name without `.gz` and extension (`E7.5-R1-C1.nwk.gz` gives `E7.5-R1-C1`), plus `_<k>` or `_<key>` for files of several trees; names must differ. The file's bytes and its trees' name identify the import.
- `ds.clones.phylogeny_clones(phylogeny, *, time=None, depth=None, invalidate_cache=False)` saves a `clones` artifact (source `"cut_phylogeny_clones"`) of the phylogeny's cells; pass exactly one cut. A clone is the clade of the first node at or past the cut below each root (as pycea's `tl.clades`); depth counts branchings with single-child nodes merged, so a root with one child is at depth 0; each child of a polytomy is its own clone; `depth=0`, or a time at or before every root's time (`time=0` unless a negative length lies above a root), gives one clone per tree. Cells whose leaves end before the cut have no clone (`n_cells_before_cut`, warned); a cut that leaves every cell out raises `ValueError`.
- Clone labels: the clade root's name when every node of its tree has a unique name (PEtracer, Cassiopeia), else `node<position>` (the `node` column of `load_phylogeny(...).nodes`); with several trees, `<tree>/` comes first.
- `ds.clones.load_phylogeny(phylogeny)` returns a `CellPhylogeny` record: `.nodes` (`tree`, `node`, `name`, `parent`, `time`, `depth`, `is_leaf`, `ids`, the leaf's cell), `.trees` (`tree`, `n_nodes`, `n_leaves`, `n_cells`, `root_time`, `earliest_leaf_time`, `latest_leaf_time`) and `.time_unit`.
- Validated on immune receptor clonotypes: every cell's category equals scirpy 0.25.1's `clonal_expansion`, frequency fractions equal scRepertoire 2.8.0's `clonalHomeostasis` and rank windows its `clonalProportion`; Hill-number curves within a relative 5.6e-11 of iNEXT 3.0.2 and closer than it to 60-digit values where the two differ most, `estimateD` within a relative 2.1e-7, every index within 6e-14 of scRepertoire 2.8.0 `clonalDiversity`, immunarch 0.10.3 `repDiversity` and vegan 2.7.6 `estimateR`; every overlap index within 5e-14 of immunarch 0.10.3 `repOverlap` and scRepertoire 2.8.0 `clonalOverlap`.

## Checks

- Compare `unmatchedBarcodes` with what the file should hold outside the store before suspecting the prefix, suffix or pattern; `unselectedBarcodes` counts cells of the store that the selection leaves out. pycashier, BARtab from BAM input and Cell Ranger's molecule info list droplets that are not cells, so their unmatched barcodes are expected.
- After calling barcode clones, read `rule_counts`: a rule that removed most molecules or barcodes, such as LARRY's `min_reads=10` on a shallow library, needs a lower threshold, given alone with the preset. LARRY's identical sets split clones whose cells lost a barcode, and so does TREX's pruning when the cells lost different barcodes; the CellTag presets keep them together.
- Then read `load_clones(clones).diagnostics`: `expectedChanceMatches` near or above a nonzero `mergedBarcodes` means correction merges unrelated barcodes, and above about a tenth of `distinctBarcodes` it chains barcodes into large clones (chance matches grow with the square of the barcodes compared; TREX's rule on synthetic clones: 0.30 per compared cloneID at 200k cells gave a 1,393-cell clone, 1.5 at 1M put 4 in 5 cells in one clone). A `largestCloneShare` far above the next clones' suggests the same chaining. The two split the work: the expectation counts how often barcodes of different components agree, so it measures chance merging while many components remain (TREX's 10x test output, one cloneID and its errors: 0.0002 expected, 89 merged), and `largestCloneShare` measures chaining, up to one component, which expects nothing while its share reads close to 1. Lower `distance`, or pass `within`, and compare the clones.
- After a barcode import, check `loaded.libraries`: each library's `level` and whether it counts UMIs and reads decide which filters clone calling can apply. Most cells should hold a few barcodes in `plots.barcode_calls`; one-read molecules and one-UMI barcodes are mostly errors and ambient reads.
- After an allele import, check `loaded.files`: each file's `format`, `integration` and `pipeline`. CARLIN's MATLAB notation and darlin-core's place some events one base apart, so alleles of the two pipelines never compare. A large `n_beyond_length` means a tape length in `integrations` is wrong.
- After calling allele clones, read `bank_coverage` (counts, not shares): a bank lists few of an experiment's distinct alleles, but it should list the frequent ones that hold most observations; a bank that lists few cells' alleles is in another notation (CARLIN MATLAB against darlin-core), and its missing alleles count as rare and join unrelated clones. Many `cells_in_clones_with_too_many_alleles` mean a frequent allele joined clones: lower `max_frequency` or `max_samples` rather than raise `max_alleles`. Without a bank, large clones' alleles look frequent.
- Check `plots.recorder_states` before building trees: a site mostly missing adds little, and one whose cells are nearly all marked or nearly all unedited separates few lineages. Trees come from Cassiopeia or LAML on the exported matrix; the export's warning counts the cells and integrations of several alleles, of which it kept the most abundant.
- Check `table.clones["n_cells"]` against the study's reported clone count and sizes; LARRY's in vitro and cytokine sets hold only clones of two or more cells, while TREX keeps singletons.
- With several files, check that `table.clones["clone"]` carries each file's namespace, and that clones expected to span samples were called jointly in one run; clones of separate runs never merge.
- Measure expansion and diversity `group_by` the sample: without it, a clone's cells in all samples add up. Frequency categories depend on sample size (one cell of 1,000 is already 0.001), so compare them only between samples of similar size; bounds in cells compare any samples.
- Compare diversity by Hill numbers at a common coverage or size (`hill.at_coverage`, `hill.at_size`), not observed indices, which grow with the cells sampled. Check `plots.clonal_rarefaction`: steep curves at the observed point mean richness and Chao1 are poorly determined; order 2 is stable. Name the Chao1 form reported. Leave out tiny groups with `cell_selection`, or set `size`/`coverage`, since the smallest group sets the defaults.
- Read overlap by the Morisita-Horn index and the shared fractions; presence indices (Jaccard, Sørensen, overlap, cosine) grow with both groups' cells, so compare them only between pairs of similar depth. A clone seen in one group only may be below detection in the others.
- Measure coupling on the cells of one time point (`cell_selection`) and read `z_score` as a ranking: shuffled labels spread each clone over every group, so when clones commit to few fates most pairs fall below the null. Keep `share_cosine` unless a few large clones should dominate. Coupling treats cells as exchangeable: it is exploratory within one sample.
- For fate bias, `early` and `late` must share no cell. Every early cell of a clone gets its clone's fractions, so summarise by clone; report how many early cells have late clone-mates. Small clones cannot reach small p-values. When barcode detection differs between cell types, pass only late cells with a clone as `late`.
- Compare conditions with one value per sample (such as the fraction of cells in clones of more than two cells), never with cells as replicates; test such values with a method that treats samples as replicates, such as CytePool's (https://docs.nygen.io/CytePool/).
- After importing a phylogeny, check its diagnostics' `unmatchedBarcodes` (leaves naming no cell of the store) and `n_cells_in_no_tree`; cut at several times, not one, and check `leaf_time_spread` and `n_cells_before_cut` for cuts near the leaves.
